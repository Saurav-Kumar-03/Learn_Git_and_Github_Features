/*
  * ===================================================================
  * GIT ARCHITECTURE: THE 3 AREAS & FILE TRACKING
  * ===================================================================
  *
  * PART 1: THE THREE AREAS OF GIT
  * -------------------------------------------------------------------
  * To understand how Git saves versions, imagine a factory workflow:
  *
  * 1. THE WORKING DIRECTORY (The Workbench)
  * - This is your actual project folder on your computer.
  * - You create, edit, and delete files here. Git sees everything you
  *   do, but it DOES NOT save these changes as a version yet.
  *
  * 2. THE STAGING AREA (The Loading Dock / Index)
  * - This is the "waiting room."
  * - Command used: 'git add <file>'
  * - When you finish working on a file, you push it to the Staging Area.
  *   You are telling Git: "I am happy with this specific file, put it on
  *   the truck to be saved."
  *
  * 3. THE LOCAL REPOSITORY (The Permanent Vault)
  * - This is where the actual versions are saved permanently.
  * - Command used: 'git commit -m "message"'
  * - When you commit, Git takes a snapshot of everything currently sitting
  *   in the Staging Area (the loading dock) and locks it into history as
  *   a brand new version of your project.
  *
  *
  * PART 2: FILE STATES (How Git sees your files)
  * -------------------------------------------------------------------
  * Inside the Working Directory, Git categorizes files into three states:
  *
  * 1. Untracked Files:
  *    Brand new files you just created. Git says, "I see this file, but
  *    I am ignoring it until you explicitly use 'git add' on it."
  *
  * 2. Tracked Files:
  *    Files that Git already knows about from previous commits. If you
  *    edit them, Git flags them as "Modified."
  *
  * 3. Ignored Files:
  *    Files that you explicitly tell Git to NEVER look at.
  *
  *
  * PART 3: THE .gitignore FILE (The Bouncer)
  * -------------------------------------------------------------------
  * You noted that some files should not be tracked by Git.
  * For example:
  * - Compiled code (like Maven's 'target/' or Gradle's 'build/' folders)
  * - Passwords, API keys, and secret database credentials.
  * - IDE configuration files (like '.idea/' or '.vscode/').
  *
  * The Solution:
  * You create a simple text file in the root of your project named exactly:
  * .gitignore
  *
  * Inside this file, you list the names of folders or files you want
  * Git to ignore. Git will act like those files do not exist and will
  * never accidentally push them to the Staging Area.
  */

  /*
   * ===================================================================
   * HOW TO DELETE A LOCAL GIT REPOSITORY
   * ===================================================================
   *
   * THE CONCEPT:
   * Running 'git init' simply creates a hidden folder named '.git' inside
   * your project. This folder IS the repository. To remove Git tracking,
   * you just delete this folder.
   *
   * WARNING:
   * Deleting the '.git' folder will instantly permanently delete your entire
   * local commit history and branches. However, it will NOT delete your
   * actual project files (your code remains perfectly safe).
   *
   * METHOD 1: USING THE TERMINAL
   * -------------------------------------------------------------------
   * First, ensure your terminal is inside the project directory.
   *
   * - Mac / Linux (Terminal):
   *   rm -rf .git
   *
   * - Windows (Command Prompt):
   *   rmdir /s /q .git
   *
   * - Windows (PowerShell):
   *   Remove-Item -Recurse -Force .git
   *
   * METHOD 2: USING THE GRAPHICAL INTERFACE (Mouse & Keyboard)
   * -------------------------------------------------------------------
   * 1. Open your project folder in File Explorer (Windows) or Finder (Mac).
   * 2. Enable "Show Hidden Files":
   *    - Windows: Click 'View' at the top -> Check 'Hidden items'.
   *    - Mac: Press [Cmd + Shift + Period(.)] on your keyboard.
   * 3. You will now see a faded folder named '.git'.
   * 4. Simply delete it and empty your trash/recycle bin.
   *
   * VERIFICATION:
   * To confirm Git is gone, open your terminal in the folder and type:
   * git status
   * It should return an error saying: "fatal: not a git repository"
   */
